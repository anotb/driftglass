# Innovation audit

Driftglass adopts newer Cloudflare agent primitives when they make personal intelligence more durable, contextual, portable, or inexpensive. It keeps deterministic infrastructure where that is clearer and more reliable.

## Agent-native product capabilities

| Capability | Driftglass role |
|---|---|
| Cloudflare Computer | One durable working directory per Mission, plus optional isolate execution |
| Kitesurf | Default rendered browser for public pages and social previews |
| Agents SDK / MCP | Compact read-only reasoning App plus separately connected operations control plane |
| Workflows | Mission Sprints, phased Memory maintenance, and deterministic Intelligence Routines |
| WebMCP | Browser-agent actions over the existing dashboard |
| Email Workers | Always-on signal inbox |
| Cloudflare Drop | Portable forkable intelligence artifacts |
| Workers Analytics | Aggregate request and CPU metrics plus content-free readiness and component telemetry |
| AI Search | Optional semantic retrieval over rebuildable Driftglass documents |
| Agent Memory | Optional approved-checkpoint projection while the service remains private beta |

## v0.9 agent-first additions

| Addition | Why it is agent-first without becoming model-dependent |
|---|---|
| Agent Runtime Fabric | Selects Worker, Kitesurf, Chromium, Computer, or Companion from task requirements and budget without exposing infrastructure choices in the UX |
| Evidence-State Receipt | Gives any reasoning model exact hashed context, provenance, temporal memory, blockers, and an output contract |
| Judgment Loop | Preserves provider-neutral model results, review, decisions, outcomes, and calibration without hosting a mandatory model |
| Temporal checkpoints | Lets agents compare what was known or believed at two reproducible graph states |
| Evidence lineage | Distinguishes independent corroboration from echoes before tokens are spent |
| Intelligence Routines | Packages bounded analyst methods as durable Workflows rather than opaque prompt loops |
| Pack overlays | Lets community intelligence evolve upstream without erasing local customizations |
| Forkable Drops | Turns a selected intelligence artifact into a static share plus a cloud-only Pack another user can continue |
| Living dossiers | Provides a deterministic thesis, chronology, contradiction, and gap surface rather than a generated generic summary |

## Dependable substrate

| Capability | Purpose |
|---|---|
| D1 | Canonical global graph, joins, approvals, receipts, decisions, and migrations |
| R2 | Evidence, checkpoints, exact receipts, results, and generated artifacts |
| Queues | Idempotent ingestion and source-failure isolation |
| Cron | Low-cost schedule evaluation |
| Chromium | Compatibility fallback after Kitesurf |

The global index and Mission workspace have different jobs. D1 makes intelligence history queryable; Computer gives one persistent question a natural working directory.

## Execution ladder

1. **Cloud-only core:** deterministic collection, lineage, memory, Packs, budgets, and context compilation.
2. **Filesystem-only Mission Computer:** durable Mission context without requiring an execution backend.
3. **Local Companion mirror:** signed-in source access and ordinary files for local tools, coding agents, Git, backup, and offline work.
4. **Computer Power Mode:** Worker-shell and Worker-JavaScript transforms against the same workspace.
5. **Full Linux backend:** future opt-in only for jobs that genuinely need native packages or background processes.

## Things not forced into the core

- a mandatory model API
- a built-in general chat agent
- a model call per collected item
- a mandatory Companion
- mandatory AI Search or Agent Memory
- a vector database as canonical truth
- a container for every Mission
- a second autonomous research engine
- a model router or multi-agent debate layer
- Cloudflare Artifacts while it is not a broadly available Free-core primitive

## Product test

A feature belongs in the core when it materially improves continuity, provenance, meaningful-change detection, durable memory, model-interface quality, user ownership, or deployment simplicity. Newness alone is not sufficient.
